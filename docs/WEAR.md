# 시계(Wear OS) 앱

러닝과 헬스를 손목에서 조작합니다. **폰 앱이 있어야 동작하는 짝꿍 앱**이라서
폰과 시계에 같은 버전을 모두 설치해야 합니다.

| 하는 일 | 설명 |
| --- | --- |
| 러닝 보기 | 거리 · 시간 · 현재 페이스 · 일시정지/자동 일시정지/신호 끊김 표시 |
| 러닝 조작 | 일시정지 · 계속 · 종료(종료는 한 번 더 확인) |
| 러닝 시작 | 대기 화면의 **러닝 시작** 버튼. 자유 러닝으로 시작합니다 |
| 헬스 세트 | 지금 할 세트(종목 · 몇 번째 세트 · 무게 × 횟수)를 보고 **완료** 한 번으로 기록 |
| 휴식 타이머 | 남은 시간 · −15초 · +15초 · 멈춤/계속 · 건너뛰기 · 끝나면 손목 진동 |
| 워치페이스 칩 | 러닝 · 휴식 · 세트 중에는 앱을 닫아도 워치페이스 아래 "진행 중" 칩이 남아 누르면 앱으로 돌아옵니다 |
| 타일 | 쓸어 넘기면 지금 러닝이나 세트를 보여 주고, 누르면 앱이 열립니다 |

운동 기록(세트 값 입력 · 무게 수정)은 폰에서 합니다. 시계는 보여 주고 조작하는 쪽입니다.

### 헬스 세트 완료는 이렇게 동작합니다

* 폰의 **운동 화면이 열려 있는 동안** 시계에 지금 할 세트가 뜹니다. 세트 완료와 휴식 타이머 시작을 그 화면이 처리하기 때문입니다.
  운동 화면을 닫으면 시계의 세트 화면도 사라집니다(운동 기록은 그대로입니다).
* 시계의 **완료**는 폰에서 완료 버튼을 누른 것과 똑같이 처리되어, 휴식 타이머도 그대로 시작됩니다.
* 슈퍼셋은 A, B, A, B 순서로 번갈아 보여 줍니다.
* 시계가 보고 있던 세트를 그사이 폰에서 먼저 끝냈다면, 시계에서 같은 세트를 또 눌러도 **다음 세트가 끝나지 않습니다**
  (눌린 세트 번호를 함께 보내서 폰이 확인합니다).
* 횟수가 비어 있는 세트는 시계에서 완료할 수 없고 "폰에서 값을 입력해 주세요"가 나옵니다.

### 시계에서 러닝 시작은 이렇게 동작합니다

* 폰 앱 화면이 **눈앞에 있으면** 바로 시작합니다.
* 폰이 주머니 속이거나 화면이 꺼져 있으면, 안드로이드가 앱이 몰래 위치 서비스를 시작하는 것을 막습니다(안드로이드 12 이상).
  그래서 폰에 **"러닝 시작" 버튼이 있는 알림**이 뜨고, 그 버튼을 누르면 시작됩니다. 시계에는
  "폰에 요청했어요. 폰 알림에서 '러닝 시작'을 눌러야 할 수 있어요."가 잠깐 나옵니다.
* 폰 위치 권한이 없으면 시작하지 못하고, 앱을 열어 허용하라는 알림이 뜹니다.
* 러닝 · 헬스를 이미 하는 중이면 무시합니다.

## 요구 사항

* Wear OS 3 이상(갤럭시 워치 4 이상, 픽셀 워치 등). 타이젠 워치(갤럭시 워치 3 이하)는 안 됩니다.
* 폰과 시계가 블루투스로 연결되어 있고 폰에 Google Play 서비스가 있어야 합니다.
* 폰 앱과 시계 앱은 **앱 ID · 서명 키 · 버전이 같아야** 합니다. 한쪽만 업데이트하면 시계가 상태를 못 받을 수 있습니다.

## 설치하기 (Play 스토어를 거치지 않는 방법)

Play 스토어에 올리지 않았으므로 **ADB 로 시계에 직접 설치**합니다(PC 가 필요합니다).
릴리즈(Releases)의 `health-wear-<버전>.apk` 를 받아 둡니다.

### 1. 시계에서 개발자 옵션 켜기

1. 시계 설정 > 시계 정보 > 소프트웨어 정보 > **소프트웨어 버전**을 7번 누릅니다(개발자 모드 켜짐).
2. 설정 > 개발자 옵션에서 **ADB 디버깅**과 **Wi-Fi 디버깅**을 켭니다.
3. 시계가 PC 와 같은 Wi-Fi 에 연결되어 있어야 합니다.

### 2. PC 에서 연결하고 설치하기

```bash
# 시계의 Wi-Fi 디버깅 화면에 나온 IP 와 포트를 씁니다
adb connect 192.168.0.23:5555
adb install -r health-wear-0.11.1.apk
```

* 갤럭시 워치는 "Wi-Fi 디버깅" 화면에서 **새 기기 페어링**(페어링 코드와 포트가 따로 나옴)을
  먼저 해야 할 수 있습니다: `adb pair <IP>:<페어링 포트>` 후 코드 입력, 그다음 `adb connect <IP>:<연결 포트>`.
* `adb` 는 안드로이드 SDK platform-tools 에 들어 있습니다.
* 이미 설치된 상태에서 업데이트할 때도 같은 명령입니다(`-r`). 서명 키가 같아서 기록 · 설정이 남습니다.

PC 가 없다면 폰에서 시계로 APK 를 넣어 주는 "Wear Installer" 같은 앱이 있지만, 이 프로젝트가 확인한 방법은 위의 ADB 입니다.

### PC 없이 폰으로 설치하기 (확인되지 않은 방법)

PC 대신 폰의 앱이 시계에 연결해서 설치할 수도 있습니다. Play 스토어의 **Wear Installer 2**, **Bugjaeger** 같은 앱이 그 역할을 합니다.
시계에서 개발자 옵션의 **ADB 디버깅 · Wi-Fi 디버깅**을 켜 두고(위 1단계), 폰과 시계를 같은 Wi-Fi(또는 폰 핫스팟)에 연결한 뒤,
앱에서 시계의 IP · 포트로 연결해 받아 둔 `health-wear-<버전>.apk` 를 고르면 됩니다. 이 방법은 이 프로젝트에서 직접 확인하지 못했습니다.
막히면 위의 PC ADB 방법이 확실합니다.

### 3. 확인

1. 폰의 Health 앱을 한 번 엽니다(처음에 상태를 시계로 올려 보냅니다).
2. 시계 앱 목록에서 **Health** 를 엽니다. "폰에서 운동이나 러닝을 시작하면 여기에 나타나요." 가 보이면 정상입니다.
3. 폰에서 러닝을 시작하면 시계 화면이 러닝 화면으로 바뀝니다. 헬스 세트를 완료해 휴식 타이머가 돌면 휴식 화면이 나옵니다.

## 동작 방식(알아 두면 좋은 것)

* 폰이 러닝 상태와 휴식 타이머를 Wearable Data Layer 로 올립니다. 시계는 경과 시간과 남은 시간을 **스스로 세므로**
  블루투스가 잠깐 끊겨도 숫자가 멈추지 않습니다. 1분 넘게 새 상태가 없으면 "폰과 연결이 끊겼을 수 있어요"라고 알립니다.
* 시계에서 누른 버튼은 폰에 메시지로 갑니다. 폰은 **지금 상태에 맞을 때만** 실행합니다
  (이미 끝난 러닝의 "일시정지" 같은 늦은 입력은 무시).
* 시계가 없어도 폰 앱은 똑같이 동작합니다. 시계로 보내는 일은 실패해도 조용히 넘어갑니다.
* 휴식 타이머가 돌 때는 시계 화면이 꺼지지 않습니다. 러닝 중에는 시스템 설정에 따라 화면이 꺼지고 시계 앱이
  백그라운드로 가지만, 워치페이스 아래 칩이 남아 있어서 누르면 바로 돌아옵니다. 폰의 러닝 알림도 시계에 자동으로
  전달되어 거기서 일시정지 · 종료 버튼을 누를 수도 있습니다.

## 알려진 한계

* 컴플리케이션(워치페이스에 직접 넣는 작은 표시)은 없습니다. 칩과 타일만 있습니다.
* 타일은 숫자를 스스로 갱신하지 못해, 폰이 소식을 보낼 때(러닝은 몇 초마다) 새로 그려집니다. 칩의 시계는 시스템이 알아서 흘러서 멈추지 않습니다.
* 폰 앱이 죽거나 연결이 끊겨 1분 넘게 소식이 없으면, 칩과 세트 화면은 지나간 운동을 붙들고 있지 않고 스스로 사라집니다.
* 시계 앱은 알림 권한이 있어야 칩을 띄울 수 있습니다(Wear OS 4 이상). 처음 열 때 허용 창이 뜹니다. 거절해도 앱은 그대로 쓸 수 있습니다.
* 시계에서 심박을 재지는 않습니다. 심박은 시계가 Health Connect 에 남긴 기록을 폰 러닝 상세에서 읽어 보여 줍니다(폰 설정 > Health Connect).
* 실제 시계에서의 동작(블루투스 지연, 진동 세기, 화면 꺼짐)은 자동 테스트로 확인할 수 없어서, 처음 쓸 때
  한 번 직접 확인해 주세요.
